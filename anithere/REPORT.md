## Is the engine ready? (the playbook, §1)

* Command registry with id, label, menu, shortcut, params: **yes**.
* Params docs that are prose rather than `{…}`: 0. These get a form with only a JSON box.
* Headless backend: **not found by name**; the FFI crate needs one.
* Requests to the front end (a queue commands push to): **not found**; commands that need a picker or dialog will do nothing until the engine has one.

## What was translated

* `Profile.kt`: the tabs in the desktop's order, and first guesses at the pointer, state-reader and typing sets.
* `Theme.kt`: light and dark schemes from the desktop theme's accent and backgrounds.
* `Workspace.kt`: the panels and tools the desktop declares.
* `Icons.kt`: Lucide icons for 32 commands (as buttons in the command bar when they ask for nothing) and 15 tools, by the ids the Craft engines share; the rest are named menu entries.
* `dialogs/`: 8 dialogs, each with the desktop dialog's controls in its order.
* `App.kt`: a responsive shell on Loki Kit: command bar, all-commands list, generated forms, results, panels, tools, themes.
* `CoverageTest.kt`: the test that every command has a way to it, and off-screen screenshots.

## What was NOT translated (the work that is left)

* **The surface.** The canvas, page or timeline is painted by hand in egui. `App(surface = …)` takes its replacement; the engine's renderer supplies the pixels (the playbook, phase 5).
* **The FFI crate and platform bindings.** The app runs on `FixtureTransport` (a recorded command list, nothing executes) until they exist (phase 1).
* **Dialog behaviour.** Starting values, enabling rules, live previews and anything a dialog draws itself. Parameter names are guesses: see the table below.
* **Hand-drawn panels.** A panel with no source command shows a note. Each needs its own composable.
* **Custom widgets, context menus, drag and drop, docking layouts, keyboard handling, icons, translations.**
